# DesktopStamp 文档盖章修复需求（v3）

整理日期：2026-10-21。来源：与用户的需求问答 + 对 `src/HostAdapters/WordStampHostAdapter.cs` 等代码的阅读。

## 1. 用户环境

- 软件：Microsoft Word 365 和 WPS 文字都要支持。**先修好 Word，再在同一套架构上加 WPS。**
- 显示：多块显示器、各屏缩放比例不同（例如 150% + 100%）。
- 测试：允许在本机编译，并用新建的临时文档实际启动 Word/WPS 测试；不得操作用户自己的文档。

## 2. 现存问题（用户反馈）

| # | 现象 | 代码层面的初步判断（待验证） |
|---|---|---|
| P1 | 在第 1 页盖章，章出现在第 2 页 | **已实测确认（与 DPI 无关）**：Word 365 是按显示器感知 DPI 的，文字附近两块屏都准。问题出在页面空白处：`RangeFromPoint` 返回的是**下一页第一个字符**，代码把这一页当成目标页，章就被锚到并按下一页定位 |
| P2 | 拖着印章在 Word 上方移动时卡顿 | 瞄准期间持续通过跨进程 COM 调 `RangeFromPoint`/`GetPoint`/`Information`，占用 Word 界面线程 |
| P3 | 点击到印章出现很慢 | 盖章路径上有大量重复 COM 校验（映射、插入前、插入后各验证一次）+ 生成并写入原尺寸 PNG |
| P4 | 盖章后 Word 变卡 | 每个章都是一张新的原始分辨率 PNG（随机墨迹），文档体积和渲染负担逐章累积 |

## 3. 目标行为

1. **位置准确**：印章中心落在准星中心，误差 ≤ 1 mm；在任一显示器、任一缩放比例、Word 任一视图缩放下都成立；不能跑到其他页。
2. **固定在页面**：印章按页面定位，正文增删不会让印章移动或换页。
3. **衬于文字下方**：环绕方式改为“衬于文字下方”，黑字完整压在红章上。
4. **延迟**：盖章动画（约 0.3 秒）结束时印章已出现在文档中。
5. **拖动流畅**：在 Word 上方移动印章时不掉帧，Word 本身不卡。
6. **盖章后不拖慢 Word**：连续盖几十个章后 Word 编辑、滚动依旧流畅。
7. **保留随机效果**：每次 ±1~3° 随机角度抖动 + 随机墨迹纹理。插入的图片按打印分辨率（约 300 dpi，40 mm ≈ 470 px）降采样，控制体积。
8. **可编辑**：盖好的章是普通对象，可选中、删除；**一次 Ctrl+Z 撤销整个章**（用 `UndoRecord` 包成一步）。
9. **出错可诊断**：失败原因要区分（不在页面上 / 视图变化 / COM 超时 / 异常），并写日志，不再统一显示“请移到 Word 文档页面”。

## 4. 修复思路（待实现时验证）

- 坐标：（实测后调整）DPI × 缩放的比例在 Word 365 下足够准确，真正的问题是页码判断，见第 6 节。锚点取目标页上离点击点最近的文字，该页没有命中文字时取页首字符。
- 性能：瞄准阶段降低探测频率、只做轻量判断；盖章阶段合并重复校验，PNG 降采样后再插入。
- 环绕与撤销：`wdWrapBehind`，`Application.UndoRecord.StartCustomRecord/EndCustomRecord`。

## 5. 第二阶段：WPS

- WPS 窗口类名、进程名（`wps.exe`）、COM ProgID（`KWps.Application`）和 Word 不同，需要独立的适配器，复用同一套坐标与插入逻辑。
- 具体差异在 Word 修好后再调研。

## 6. 实施状态（2026-10-21，Word 部分）

| 项 | 状态 | 做法 / 实测 |
|---|---|---|
| P1 跨页偏移 | 已修复 | 不再相信 `RangeFromPoint` 的页码：先用命中文字所在页做参照，点击点不在该页就依次试 ±1、±2 页（用页首字符做参照），选真正包含点击点的那一页。100%/150% 两块屏、100%/140% 缩放、文字旁与空白处共 20 个点全部落在正确页，误差 0.26~0.94 mm |
| 衬于文字下方 | 已完成 | `wdWrapBehind` |
| 一次撤销 | 已完成 | `UndoRecord.StartCustomRecord("盖章")`，实测一次 Undo 移除整章 |
| 图片体积 | 已完成 | 按 300 dpi 打印尺寸降采样（导入的大图章约减少 65% 像素） |
| P2 拖动卡顿 | 已优化 | 移动中、滚动/缩放刚发生时只做轻量探测（窗口、视图、缩放），静止下来后只做一次完整映射 |
| P3 出章延迟 | 已优化 | 两阶段：按下鼠标即入队做只读准备（页面缓存 + 并行编码 PNG），落章那一刻（约 63 ms）才允许 `AddPicture`；插入后的属性设置从 13 次减到 7 次。单次盖章 330~600 ms → 185~270 ms；点击到印章出现：100% 屏约 230~250 ms，150% 屏约 250~310 ms（动画 210 ms） |
| P4 盖章后变卡 | 已优化 | 主要是瞄准状态下持续的完整探测占用 Word，现已改为每次静止只做一次；图片降采样 |
| 出错可诊断 | 已完成 | 失败原因区分（连接 Word 失败 / 插入失败 / 视图变化 / 不在页面上）；每次盖章的阶段耗时写入 `%LOCALAPPDATA%\DesktopStamp\logs\stamp-日期.log` |

验证方式：`tools/WordPlacementRepro` 会启动独立的 Word 实例和临时文档（已有 Word 在运行时拒绝执行），在已知页面位置画绿色标记、截屏得到真实像素，再检查探测和盖章的页码、坐标误差、环绕方式、一次撤销和端到端耗时。

```powershell
& "C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe" tools\WordPlacementRepro\WordPlacementRepro.csproj /p:Configuration=Release
.\dist-v2\repro\DesktopStamp.WordPlacementRepro.exe
```

运行期间会把 Word 窗口临时置顶并在各显示器间移动，请不要操作电脑。

已知限制：
- Word 没有"把浮动图片钉死在某一页"的能力，印章必须锚在某个段落上。现在锚在点击处所在页最近的文字上、按页面定位，同页内增删文字不会移动印章；但如果前面的内容增删导致这个锚点段落换了页，印章会跟着换页。
- 离参照文字越远误差越大（Word 实际渲染比例与 DPI × 缩放有 0.1%~0.35% 的差异），最坏实测 0.94 mm。
- 150% 屏上印章大约在动画结束后 40~100 ms 才出现，剩余时间是 Word 自身的 `AddPicture` 加 7 次属性设置。
